# ADR-0005: FEOD-структура фронтенда и проверка границ

- Дата: 2026-11-04.
- Статус: **принято пользователем** при постановке задачи о разложении фронтенда по FEOD.

## Context

Фронтенд инициализирован как плоский набор файлов: `src/health/`, `src/routes/`, entry, router и theme в корне `src/`. По мере роста stories #1–#8 это привело бы к смешению маршрутов, доменной логики и общих компонентов. Нужна структура, которая масштабируется по модулям и проверяется автоматически, без введения монорепо, SSR или дополнительного state-менеджера.

## Decision

- **Решили:** организовать `frontend/src/` по FEOD в базовом варианте: слои `app`, `pages`, `modules`, `common`, `globals`; `srcRoot` — `src`, alias — `@`.
- **Почему:** слои разделяют bootstrap, URL-страницы и доменные модули; модули публикуют только `index.ts`; страницы остаются тонкими. Это соответствует размеру MVP и не мешает развивать модули вложенными подмодулями.
- **Решили:** зафиксировать вариант в `frontend/feod.profile.md`, машинно читаемые поля — в `frontend/package.json#feod`, и включить `@o-feod/eslint-structure-plugin` в существующий ESLint.
- **Почему:** одно объявление структуры для людей и линтера; правила импортов, публичного API модулей и файлов вне слоёв проверяются в `pnpm lint`, а не только соглашением.
- **Отвергли:** commonless и multiapp — в проекте есть общие утилиты и одно приложение; файловую маршрутизацию — TanStack Router уже объявляется вручную (ADR-0004); отдельный линтер Oxlint — ESLint уже выбран.

## Consequences

- Новый код размещается в соответствующем слое; доменная логика — в `modules/<Name>/`, а не в `pages` или `app`.
- Межмодульные импорты идут только через `@/modules/<Name>`; общие сущности сначала попадают в `common`, при росте выделяются в модуль.
- Нарушения структуры ломают `pnpm lint`. Профиль и `package.json#feod` меняются вместе; второй источник конфигурации (`feod.config.json`) не создаётся.
- Физическое расположение файлов не меняет HTTP-контракт, маршруты и поведение экрана готовности.
