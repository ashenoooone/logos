# ADR-0007: решения для оставшихся историй #4–#8

- Дата: 2026-11-04.
- Статус: **принято пользователем** («со всем согласен»).
- Основание: блок вопросов по [открытым вопросам](../open-questions.md) для #4–#8 с предложенными вариантами по умолчанию.

## Context

После закрытия #1–#3 остались #4 (без восстановления пароля), #5–#8. Тексты историй не задают ряд правил: подтверждение смены email, работу с Telegram Bot API, права и прочитанность диалогов, теги, фильтры. Макеты #5–#8 ещё не открыты и не сопоставлены: решения ниже приняты по текстам историй. Если макет им противоречит, конфликт выносится пользователю, а не решается молча.

## Decision

### #4 — смена email, пароля и профиль

- **Решили:** ссылка подтверждения нового email одноразовая, действует 24 часа. До подтверждения вход по старому email.
- **Решили:** если новый email занят, сразу показывать «Email занят». Действие доступно только вошедшему пользователю, поэтому риск раскрытия адреса небольшой.
- **Решили:** уведомление на старый адрес не отправлять. Сессии при смене email не отзывать.
- **Решили:** в профиле меняются только имя, email и пароль.
- **Отвергли:** уведомление на старый адрес, отзыв сессий при смене email, нейтральный ответ при занятом email.

### #5 — каналы Telegram

- **Решили:** получать обновления long polling (`getUpdates`), не webhook.
- **Почему:** не нужен публичный HTTPS-домен; работает локально.
- **Отвергли:** webhook до появления production-среды.
- **Решили:** один бот на установку. Токен хранится в SQLite открытым текстом и никогда не возвращается через API. Неверный токен определяется проверкой через Bot API при подключении.
- **Отвергли:** шифрование токена ключом из env на этом этапе; несколько ботов.
- Компромисс: токен в открытом виде защищён только доступом к файлу БД. Шифрование добавить вместе с production-развёртыванием.
- **Решили:** при переподключении накопленные за время отключения сообщения не забирать, принимать только новые. Повторное событие отбрасывать по `update_id` и по паре чат + `message_id`.

### #6 — входящие и ответы

- **Решили:** принимать только личные чаты с ботом, без групп и каналов.
- **Решили:** поддерживать текст, фото и документы. Остальные типы показывать как «неподдерживаемое сообщение». Лимиты размера файлов — по Bot API; перед реализацией проверить по документации.
- **Решили:** «доставлено» означает успешный ответ Bot API на отправку. Фактическую доставку на устройство клиента Bot API не сообщает.
- **Отвергли:** имитацию подтверждения доставки на устройство.
- **Решили:** все менеджеры видят все диалоги и могут отвечать, без назначения ответственного. Администратор не видит «Входящие» и не отвечает.
- **Решили:** прочитанность общая на компанию: открыл один менеджер — прочитано у всех. Общий счётчик — сумма непрочитанных по всем диалогам.
- **Отвергли:** личную прочитанность для каждого менеджера.
- **Решили:** новые сообщения доставляются в браузер опросом раз в 3–5 секунд.
- **Отвергли:** WebSocket/SSE на этом этапе.
- **Решили:** при неизвестном результате отправки (таймаут, сетевая ошибка) ставить «Не доставлено». Повтор только вручную, с предупреждением о возможном дубле. Текст ответа сохраняется.
- **Решили:** вложения хранятся файлами на диске рядом с SQLite, отдаются только через API после проверки сессии.

### #8 — теги

- **Решили:** имя тега уникально в рамках компании без учёта регистра. Внешние пробелы обрезаются.
- **Решили:** теги на диалогах видны всем менеджерам. В подсказках выбора — стандартные теги и свои теги менеджера.
- **Решили:** менеджер не переименовывает свои теги, только удаляет. Стандартные теги меняет и удаляет только администратор.
- **Решили:** начальный набор стандартных тегов пустой. Число тегов на диалог не ограничено.

### #7 — сортировка и фильтры

- **Решили:** сортировки: по последнему сообщению (новые сверху — по умолчанию; старые сверху) и по числу непрочитанных.
- **Решили:** фильтры: канал, тег, есть непрочитанные. Значения внутри одного фильтра — ИЛИ, разные фильтры — И.
- **Решили:** выбранная сортировка и сохранённые наборы фильтров хранятся на сервере, у каждого менеджера свои.
- **Решили:** N в «N новых сообщений» — число новых сообщений. «Просматривает список» — открыта страница «Входящие».

### Доставка писем

- **Решили:** до production оставаться на локальном SMTP/Mailpit из [ADR-0006](0006-first-authentication-scenario.md), включая письма #4. Реальный почтовый сервис подключается вместе с production-развёртыванием.

## Consequences

- Для #4–#8 блокеров требований нет, кроме сопоставления макетов #5–#8 перед UI-реализацией каждой истории.
- Long polling требует фонового процесса опроса в бэкенде; вместе с единственным писателем SQLite это согласуется с одним воркером Uvicorn.
- Общая прочитанность и отсутствие назначения ответственного упрощают модель; если позже понадобится распределение диалогов, потребуется новое решение.
- Открытый токен бота и внешняя доставка писем остаются задачами production-развёртывания.
