# ADR-0004: техническая инициализация фронтенда

- Дата: 2026-11-04.
- Статус: **принято пользователем** при выполнении `docs/frontend-handoff.md`.

## Context

React, Mantine UI, pnpm и TanStack Router уже приняты в ADR-0001 и ADR-0003. Бэкенд предоставляет только `GET /health`; CORS не настроен. Нужна запускаемая клиентская SPA без реализации stories #1–#8.

## Decision

- **Решили:** TypeScript + Vite; Node.js 24 LTS; ESLint, TypeScript type-check, Vitest + Testing Library для проверок. Фронтенд изолирован в `frontend/`, без workspace и монорепо-инструментов. Совместимые точные версии фиксируются в манифесте и `pnpm-lock.yaml` при установке.
- **Почему:** пользователь выбрал TypeScript + Vite из предложенных вариантов; типизация поддерживает HTTP-состояния и маршруты, Vite обеспечивает минимальную SPA-сборку и dev proxy. Node.js 24 LTS доступен локально. Vitest использует ту же среду сборки, Testing Library проверяет наблюдаемое поведение React.
- **Отвергли:** JavaScript без статической типизации; SSR, TanStack Start, TanStack Query и глобальный store для одного health-запроса.

- **Решили:** маршруты TanStack Router объявляются вручную в коде.
- **Почему:** пользователь выбрал этот вариант; сейчас нужны только главная и обработка неизвестного пути.
- **Отвергли:** файловые маршруты с плагином и генерацией дерева на текущем этапе.

- **Решили:** браузер запрашивает относительный `/health`; Vite proxy направляет его в существующий бэкенд. Production-хостинг должен отдельно маршрутизировать `/health` в бэкенд и обеспечивать SPA fallback для клиентских URL.
- **Почему:** сохраняется same-origin-подключение без изменения HTTP-контракта и CORS.
- **Отвергли:** широкое разрешение CORS и публичный абсолютный адрес API в клиентской сборке без необходимости.

- **Решили (2026-11-04):** браузерную визуальную и интерактивную приёмку этого этапа пользователь выполняет вручную.
- **Почему:** после блокировки браузерного инструмента политикой `eval` пользователь явно выбрал «Проверю браузер вручную». Проверки кода и реальных HTTP-сценариев остаются за агентом и выполнены; браузерные результаты не заявляются.
- **Отвергли:** изменение разрешений инструмента ради автоматической браузерной приёмки в этой сессии.

## Consequences

- Фронтенд имеет собственные команды установки, dev, build, preview и проверок; Python-окружение остаётся в корне.
- Точные версии инструментов, фактические команды и ограничения preview/production документируются после реализации.
- Технический экран показывает реальный результат readiness-запроса, а не наличие авторизации или готовность будущих интеграций.
- Настройка production-хостинга остаётся отдельной задачей. Секреты нельзя помещать в клиентское окружение сборки.
