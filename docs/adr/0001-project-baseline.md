# ADR-0001: стартовые границы и стек Logos

- Дата: 2026-11-04.
- Статус: **принято пользователем** при инициализации проекта.
- Это первая запись журнала решений; следующие значимые решения — отдельные ADR в этой папке.

## Context

Репозиторий содержит требования, но ещё не содержит приложения. Восемь GitHub stories описывают регистрацию менеджеров, вход, управление каналами, переписку, сортировку и теги. Стек, границы установки и создание первого администратора в stories не определены.

## Decision

### Стек

- **Решили:** Python / FastAPI на сервере; React / Mantine UI на клиенте; SQLite для базы данных.
- **Почему:** пользователь явно выбрал этот набор для старта проекта.
- **Отвергли:** PostgreSQL и полностью TypeScript-стек как стартовый вариант.
- Версии, инструменты сборки, ORM, миграции, менеджеры пакетов и схема развёртывания пока не выбраны.

### Границы установки

- **Решили:** одна установка для одной компании.
- **Почему:** пользователь подтвердил однокомпанейный сценарий.
- **Отвергли:** многокомпанейную модель с изоляцией арендаторов в текущем объёме.
- Доступ конкретных менеджеров к диалогам внутри компании этим решением не определён.

### Первый канал

- **Решили:** Telegram Bot API, подключение бота по токену.
- **Почему:** пользователь выбрал его первой интеграцией для stories 3.1 и 3.2.
- **Отвергли:** подключение личного Telegram-аккаунта как трактовку первой интеграции. Остальные мессенджеры пока не выбраны и не обещаны.

### Первый администратор

- **Решили:** создаётся закрытой командой развёртывания; публичная самостоятельная регистрация не входит в текущий объём.
- **Почему:** администратор нужен до приглашения первого менеджера; пользователь выбрал этот способ начальной настройки.
- **Отвергли:** публичную регистрацию первого администратора.
- Имя команды, ввод секретов и поведение при повторном запуске нужно определить при реализации.

## Consequences

- Не выбирать другой UI-kit, СУБД или серверный фреймворк без нового согласованного решения.
- SQLite — реальное выбранное хранилище, не заглушка до появления другого сервера БД.
- Перед реализацией приёма сообщений нужно определить транзакции и поведение при конкурирующих записях: SQLite допускает только одного писателя одновременно.
- Требования об общем списке диалогов сохраняются, но первый реализуемый провайдер — Telegram Bot API.
- Нужен отдельный этап технической инициализации: в момент принятия ADR ни приложение, ни команды запуска ещё не созданы.
