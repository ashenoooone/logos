# ADR-0008: вход менеджеров по коду и правки демо

- Дата: 2026-11-07.
- Статус: продуктовые решения приняты в [#10](https://github.com/ashenoooone/logos/issues/10); параметры OTP ниже — выбранные технические значения.
- Основание: пользователь поручил реализовать #10 целиком.

## Context

#10 заменяет парольный вход менеджеров из ADR-0006 входом по одноразовому коду. Администратор остаётся без email, на прежнем входе по CLI login и паролю. Приглашение, установка пароля и изменение пароля в профиле сохраняются.

## Decision

- **Решили:** менеджер запрашивает код на email и вводит его для получения прежней cookie-сессии с CSRF-защитой. Ответ запроса нейтрален для существующего, неизвестного и ещё не активированного аккаунта. Сбой SMTP даёт общую понятную ошибку без раскрытия аккаунта или кода.
- **Почему:** согласованный в #10 сценарий не требует помнить пароль для входа и не раскрывает существование учётной записи.
- **Отвергли:** OTP для администратора, сохранение второго парольного входа менеджера и восстановление пароля менеджера.
- **Решили:** код содержит 6 случайных цифр, действует 10 минут, допускает 5 попыток; новый запрос разрешён через 60 секунд и отзывает предыдущий код. Успешное использование одноразовое; секрет кода не хранится открытым текстом и не возвращается API.
- **Почему:** ограничены срок подбора, число попыток и частота отправки; параметры явно фиксируют незаданные в #10 величины.
- **Отвергли:** неограниченные попытки, несколько действующих кодов и выдачу кода в ответе или журнале.
- **Решили:** SMTP передаёт одинаковое письмо с кодом на любой корректный email; для неизвестного или ожидающего приглашения адреса код случайный и не сохраняется как рабочий. Ошибка SMTP возвращает одинаковый `503`. Проверка соединения выполняется до изменения OTP и cooldown; ошибка последующей отправки не выдаётся за успех.
- **Почему:** иначе ошибка реальной отправки только для зарегистрированного адреса раскрывала бы наличие аккаунта, а нейтральный успех при сбое нарушал бы #10.
- **Отвергли:** разные SMTP-ответы для существующего и неизвестного аккаунта; подавление ошибки отправки.
- **Решили:** `/start` и `/start@<bot>` обновляют карточку клиента, но не создают сообщение; ранее сохранённые команды удаляются миграцией без удаления остальной переписки.
- **Почему:** команда запуска бота не является обращением клиента.
- **Отвергли:** только визуальное скрытие с сохранением неверных счётчиков и превью.
- **Решили:** поиск диалогов серверный, по всей истории текстов с Unicode-регистронезависимым сравнением; имя автора исходящего сообщения связано с менеджером через `messages.manager_id`. При повторе исходный автор сохраняется. Для старых исходящих без автора используется нейтральная подпись.
- **Почему:** все менеджеры видят общую переписку; поиск и авторство должны учитывать сообщения вне текущего экрана.
- **Отвергли:** поиск только по последнему сообщению и присвоение старым сообщениям выдуманного автора.
- **Решили:** подпись канала — «Telegram»; пользовательские теги автоматически не переименовываются. Название истории презентации — «Формирование отчёта».
- **Почему:** единые продуктовые названия из #10 без изменения пользовательских данных.
- **Отвергли:** автоматическое переименование существующих тегов.
- **Решили:** существующий тег прикрепляется по стабильному `tag_id`; имя используется только для явного создания. Каталог обновляется по существующей модели polling.
- **Почему:** переименование в другой сессии не должно создавать новый тег со старым именем при выборе прежней подсказки.
- **Отвергли:** использование отображаемого имени как идентификатора существующего тега.

## Consequences

- ADR-0006 заменён только в части входа и восстановления пароля менеджеров; вход администратора, приглашения, профиль, cookie-сессии и CSRF сохраняются.
- Backend-контракт, frontend и открытые вопросы обновляются вместе с реализацией.
- Миграции удаляют только служебные команды запуска и добавляют авторство/хранение OTP без потери остальной переписки.
