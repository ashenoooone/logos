### Чек-лист ручной браузерной приёмки

Запуск бэкенда и команды `pnpm dev` / `pnpm build` / `pnpm preview` — в README. Проверить главную, ошибку и not-found на desktop и ширине около 390 px:

1. На мигрированной БД — готовность; «Проверить снова» показывает загрузку и блокируется до ответа.
2. После остановки бэкенда и повторной проверки — неожиданный HTTP 502, не успех и не диагноз неготовой БД.
3. Для 503 использовать **только отдельный временный SQLite-путь** в `LOGOS_DATABASE_PATH`, без миграций; не удалять и не портить рабочую БД. Затем вернуть мигрированную БД и проверить восстановление кнопкой.
4. Browser DevTools → Offline, повторная проверка — «Нет связи»; вернуть Online и проверить восстановление.
5. Прямо открыть вложенный неизвестный URL, обновить страницу, перейти «На главную». Повторить на preview собранного приложения.
6. Нет горизонтального скролла, обрезанного текста и ошибок приложения в console. Проверить loading с network throttling.

## Что сделать

### 1. Окружение и запуск

- Изолировать фронтенд в понятном каталоге, предпочтительно `frontend/`; Python-окружение оставить в корне.
- Зафиксировать поддерживаемую Node.js и версию pnpm, зависимости и lock-файл.
- Реализовать реальные команды установки, dev-запуска, production-сборки, локального просмотра сборки и проверок.
- Не добавлять монорепо-инструменты и pnpm workspace без необходимости.

### 2. React, Mantine, TanStack Router

- Подключить MantineProvider и необходимые стили.
- Создать корневой маршрут и технический стартовый экран Logos, не продуктовый dashboard.
- Настроить обработку неизвестного клиентского маршрута и возврат на главную.
- Не создавать пустые страницы будущих stories, фиктивные меню, авторизационные guards или фальшивую сессию.
- Проверить прямое открытие URL и обновление страницы; описать требования SPA fallback для будущего хостинга.

### 3. Реальный HTTP

Единственный прикладной эндпоинт сейчас:

| Запрос | Ответ |
|---|---|
| `GET /health`, нужная схема SQLite доступна | `200 {"status":"ok"}` |
| `GET /health`, БД/схема не готовы | `503 {"detail":"Database is not ready"}` |

Нет API входа, профиля, регистрации, каналов или сообщений. OpenAPI и Swagger отключены.

- Технический экран должен показывать результат настоящего запроса `/health`, состояние загрузки и недоступность сервиса.
- Различать HTTP `503` и сетевую ошибку; не выдавать их за успешное подключение.
- Не использовать моки, таймер успешного ответа, localStorage-пользователя или выдуманные API.
- Бэкенд не настроен на CORS. Для разработки предпочтителен dev proxy с относительным `/health`, без изменения backend-контракта и без широкого CORS «на всякий случай».
- Не вводить TanStack Query, глобальный store, генератор API-клиента или автоматические повторы ради одного health-запроса.
- Не помещать секреты в публичную конфигурацию сборки; frontend env доступен пользователю браузера.

## Как запустить существующий бэкенд

Из корня репозитория:

```sh
uv sync --locked
export LOGOS_DATABASE_PATH="$PWD/data/logos.sqlite3"
uv run alembic upgrade head
uv run uvicorn logos_backend.app:app --host 127.0.0.1 --port 8000 --workers 1
```

`.env` автоматически не загружается. Наличие администратора для health не требуется. `uv run logos-backend create-admin --login root` создаёт администратора, но не даёт работающего входа: аутентификация ещё не реализована.

Предыдущая приёмка бэкенда: 33 теста прошли, Ruff и strict mypy успешны; реальный Uvicorn/CLI/сохранение SQLite проверены. Приёмочная БД удалена, процессы остановлены.
