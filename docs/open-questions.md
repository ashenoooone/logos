# Открытые вопросы перед реализацией

На 2026-11-04. Это пробелы требований и технические решения, а не новые обязательные функции. Закрывать перед соответствующей задачей, не блокировать ими несвязанные работы. Принятые решения — в [ADR-0001](adr/0001-project-baseline.md)–[ADR-0007](adr/0007-remaining-stories-decisions.md).

## Техническая инициализация

**Закрыто 2026-11-04 для бэкенда.** Инструменты, версии, менеджер пакетов, миграции, проверки и создание первого администратора зафиксированы в [ADR-0002](adr/0002-backend-initialization.md); реальные команды и поведение — в [README](../README.md) и [контракте бэкенда](backend-contract.md). Первый администратор создаётся интерактивной командой с двукратным скрытым вводом пароля; повтор не меняет существующую запись. Зафиксированы uv и Python 3.13, FastAPI, синхронный SQLAlchemy 2, Alembic, argon2-cffi, pytest, Ruff, mypy.

**Инструменты фронтенда выбраны и реализованы 2026-11-04.** TypeScript + Vite, Node.js 24 LTS, pnpm, React + Mantine UI, TanStack Router с маршрутами в коде, ESLint, Vitest + Testing Library. Структура `frontend/src/` — FEOD (слои `app`, `pages`, `modules`, `common`, `globals`), границы проверяет `@o-feod/eslint-structure-plugin`. Точные версии закреплены в `frontend/`; команды и dev/preview proxy `/health` — в [README](../README.md), решения — в [ADR-0004](adr/0004-frontend-initialization.md) и [ADR-0005](adr/0005-frontend-feod.md).

Осталось перед следующими этапами:

- **Браузерная приёмка технического фронтенда закрыта:** пользователь 2026-11-04 подтвердил весь чек-лист ответом «Всё проверено, замечаний нет». Это ручное подтверждение, не новый агентский прогон. Источник — [ADR-0006](adr/0006-first-authentication-scenario.md), чек-лист — в [хендоффе](frontend-handoff.md).
- **Развёртывание:** целевая среда, процесс запуска Uvicorn, постоянное расположение файла SQLite и вложений, резервное копирование. Путь к БД уже настраивается `LOGOS_DATABASE_PATH`, но production-среда и схема бэкапов не выбраны. Не определять многопроцессную схему без учёта единственного писателя SQLite.
- **Первый администратор в production:** как владелец установки получает доступ к терминалу и передаёт пароль. Сама команда реализована, но операционная процедура развёртывания остаётся неопределённой.

## Перед регистрацией и авторизацией — #1–#4

- **Макеты и объём согласованы:** поздние image.png приоритетны; список сотрудников — из LOG-33.png. Имя/email обязательны, роль фиксирована «Менеджер», письмо обязательно; отключение сотрудников исключено. В первый сценарий входят #1–#3 и восстановление из #4, не весь профиль. Конфликт с выбором роли из текста #1 разрешён явно в [ADR-0006](adr/0006-first-authentication-scenario.md).
- **Локальный первый сценарий согласован:** правила email/пароля, состояния аккаунта, блокировки, сессий, восстановления, исправления приглашения и ошибок SMTP приняты в [ADR-0006](adr/0006-first-authentication-scenario.md). Блокеров требований для его backend-реализации нет; технические настройки и HTTP-контракт документируются по факту реализации.
- **Внешняя доставка отложена до production:** до развёртывания остаёмся на локальном SMTP/Mailpit, включая письма #4 — [ADR-0007](adr/0007-remaining-stories-decisions.md#доставка-писем). Перед production потребуются реальный почтовый сервис, отправитель, URL приложения и проверка получения внешнего письма.
- **Оставшаяся #4 решена:** [ADR-0007](adr/0007-remaining-stories-decisions.md#4--смена-email-пароля-и-профиль).

## Как закрывать вопросы

- Данные из актуального макета или уточнения issue фиксировать со ссылкой на источник отдельно от неизменённого импортированного текста.
- Значимые архитектурные развилки — новый ADR со статусом proposed до одобрения; принятые решения отмечать датой, «Решили / Почему / Отвергли».
- Технические команды и пути документировать после их появления в репозитории, не заранее.
- Здесь оставлять только нерешённые вопросы; после решения давать ссылку на источник в соответствующем документе.
